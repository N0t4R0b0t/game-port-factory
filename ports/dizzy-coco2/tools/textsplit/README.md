# textsplit

Splits the port's hand-edited 6809 text sources (`target/text_src/`, `target/text_src_tape/`)
into **templates** that are safe to publish and the **original game's strings** that are not,
and puts them back together byte-for-byte.

## What is public, what is yours

| Public (in git) | Supplied by you (never in git) |
|---|---|
| `target/text_tpl/`, `target/text_tpl_tape/` templates: port code, comments, port-only strings, and `@orig(...)` keys | `extracted/game_text.json` (made by `tools/textdata` from your `X-ALL.TXT` / `PRTDIZZY.PDS`) |
| `allow.txt` (game name, character names, plain English), `categories.txt`, `nodata_allow.txt`, `port_only.txt` | the filled `target/text_src*/` directories (generated by `fill`, gitignored) |

## Key scheme

```
fcc "@orig(X-ALL:296/13)"     tag (file stem), 1-based source line, byte length
fcc "@orig(X-ALL:981#1/9)"    second string on a line that holds several (ordinal omitted when 0)
```

The length is a guard against a different `X-ALL.TXT` revision (fill fails if it differs).
**There are no transforms.** All 351 original-derived strings equal the extractor's `raw` field
exactly (`:` stays `:`), so nothing like case/space/trim rewriting is needed. A string that
equals an original only after normalisation is reported as UNMATCHED and fails `split`; add a
transform to `src/lib.rs` (and this README) only if that ever happens for real.

## Commands

All run from `ports/dizzy-coco2`; binary `tools/textsplit/target/release/textsplit`
(`cargo build --release --offline --manifest-path tools/textsplit/Cargo.toml`).

```
textsplit split --src target/text_src --orig-json extracted/game_text.json \
                --allow tools/textsplit/allow.txt --out target/text_tpl
textsplit fill  --templates target/text_tpl --orig-json extracted/game_text.json --out target/text_src
textsplit check-public --templates target/text_tpl --orig-json extracted/game_text.json \
                --allow tools/textsplit/allow.txt [--also PATH...]
textsplit roundtrip --src target/text_src --orig-json extracted/game_text.json [--no-leak-check]
textsplit check-public --docs --orig-json extracted/game_text.json --allow tools/textsplit/allow.txt \
                [--list FILE_OF_PATHS] [--also FILE_OR_DIR...] [--show-weak]
textsplit export-lua --orig-json extracted/game_text.json --out harness/orig_text.lua
textsplit scrub --orig-json extracted/game_text.json --allow tools/textsplit/allow.txt --list FILE_OF_PATHS [--apply]
```

`split` fails (writes nothing) if any `fcc` string is neither an exact original (-> key) nor
provably port-only (absent from the original set even after normalisation), if an `fcc`
line is not the simple `fcc "..."` form, if the output would leak, or if fill(split(x)) != x.
Port-only strings are printed on every run.

### How bootstrap calls fill

```
textsplit fill --templates target/text_tpl      --orig-json extracted/game_text.json --out target/text_src
textsplit fill --templates target/text_tpl_tape --orig-json extracted/game_text.json --out target/text_src_tape
```

then `dte build` as before. Fill exits non-zero (listing the keys) when the original text
is missing or is a different revision.

## Leak check

`check-public` fails if any original string whose words join to >= 4 characters occurs in the
templates (or `--also` paths) as a whole word sequence, case-insensitive, `:` and all
punctuation counting as a separator. Comment runs are scanned as one stream, so a phrase wrapped
over two `;` lines is caught. Inside an `fcc` operand nothing is exempt; in comments and code,
only the strings in `allow.txt` are. Keep `allow.txt` to the game name, character names and
ordinary words; do not add phrases of dialogue. Comments should refer to original text by line
(`X-ALL.TXT 880`) or by key, not quote it.

## Text policy and the docs gate

Running dialogue/message text is never quoted in a tracked file; identifiers (room titles, item names, UI
labels) may be. `categories.txt` maps source regions to `room | item | ui | message` (the data has no
category of its own; lines no rule covers are `message`, so a different revision fails closed).
`check-public --docs` scans arbitrary text files (`--list FILE` one path per line, `--also` files or
directories; directories are walked recursively over md lua py rs toml sh json asm txt inc cfg yml yaml,
skipping `target/`, `.git/`, `extracted/`, `text_src*/` and the generated `orig_text.lua`). Words are matched as a stream across line breaks, case-insensitive, `:` and
punctuation as separators, so a wrapped quote is found. It FAILS on:

1. a message string that reads as a quote: written in the source's own upper case with >= 3 words or >= 12
   characters, or in any case with >= 4 words (two or three words of lower-case English are prose);
2. a run of >= 3 message strings starting within 6 lines (the backstop for dialogue split into short rows).

A message string that sits inside a longer identifier ("SOME SLEEPING POTION") is not a quote. `allow.txt`
passes ordinary prose (several-word entries only when not written in upper case). Output names the key
(`[X-ALL.TXT line N]`), never the text. `--show-weak` also lists message strings too short to fail alone.
`scrub` rewrites findings into pointers (dry run by default). `export-lua` writes `harness/orig_text.lua`.

`check_docs_nodata.sh FILE...` is the data-free backstop (colon-encoded runs of >= 3 segments, minus the
identifiers in `nodata_allow.txt`); it cannot see plain-word dialogue.

Tests that need no user data: `cargo test --offline --manifest-path ports/dizzy-coco2/tools/textsplit/Cargo.toml
--test docs_cli` (synthetic strings only; never put original text in a test).

## Adding a port-only string

Write `fcc "MY:NEW:TEXT"` in a `text_src*/` file (or directly in a template). `split` classifies
it as port-only because it is not in the original set and leaves it inline. Do not add a string
that is an original one: it will be keyed instead. Port-only strings currently:
`GAME:OVER`, `PRESS:SPACE`, `AN:OBJECT`, `EXIT` (gameplay.asm); `GAME:SAVED`, `GAME:LOADED`,
`NO:SAVED:GAME`, `DISK:ERROR`, `SAVE:IS:FROM`, `ANOTHER:VERSION` (msg_data_floppy.asm).

The authoritative list is `port_only.txt` (read by `check_templates.sh`); add the string there too.

To edit a template by hand, edit `target/text_tpl*/` directly; run `fill`, then `check-public`.

## Pure-text guard

`tools/textsplit/check_templates.sh DIR...` needs no user data: every `fcc`/`fcs` operand in the
templates must be an `@orig(...)` key or a `port_only.txt` string, and `fcb`/`fdb` operands may not
contain quotes or character literals. `scripts/export-public.sh` runs it as a fail-closed gate.

## Verifier

```
cargo test --offline --manifest-path ports/dizzy-coco2/tools/textsplit/Cargo.toml
```

Unit tests cover normalisation, keys, line classification, split/fill and the leak scan.
`tests/real.rs` runs over the real files when `extracted/game_text.json` exists (otherwise it
prints `SKIPPED` and passes): byte round-trip of the legacy sources, shipped templates fill and
re-split to themselves and leak nothing, and a planted leak makes `check-public` exit 1.
